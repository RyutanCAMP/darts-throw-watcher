- 指示者：唐川
- 担当：クロ（Claude・りゅうアカウント）

## やりたいこと
Android で公式アプリ（DARTSLIVE Home）を普通にプレイしながら、刺さった場所を自作アプリ
（darts-training-lab）にも取り込み、傾向と対策を分析する。

## 分かっていること
- DARTSLIVE-200S は端末に**ハードウェアキーボード**として認識される（公式ヘルプ：https://dartslive.com/dartsboard/en/200s/help ）
- 82区画＋START/CHANGE のキー割当は darts-training-lab の `data/200s-keymap.json`（PCで実測済み）
- Bluetooth の接続先は同時に1台。機器認証も1台だけ（別の端末で認証すると前の端末は解除）

## 検討（リーダー1名＋サブリーダー3名）
| 担当 | 結論 |
|---|---|
| A：Android技術面 | ユーザー補助の onKeyEvent はアプリより先にキーを受け取れる。false を返せば公式アプリにそのまま届く。重い処理はしない（最大500msの待ちがあるため） |
| B：公式アプリとの共存・規約 | OS標準のキー入力なので共存できる見込み。規約の明文の禁止（改変・リバースエンジニアリング等）には当たらないと考える（推測）。LIVE MATCH 中は使わないのが無難 |
| C：実装・工数 | 送信は Firestore 経由が最も簡単（https のページから LAN へは直接つなげないため） |

## 実機テスト（v0.1.0-test）
- 端末：Android タブレット（公式アプリ com.dartslive.dlhome で COUNT-UP 等をプレイ）
- 結果：**合格**
  - 15・3・2 のシングル内側を投げ、S15I・S2I・S3I と正しく判定（未登録キー 0件）
  - 公式アプリが前面のまま横から拾えた（前面=com.dartslive.dlhome）
  - Shift は別のキーイベント（KEYCODE_SHIFT_LEFT）として届くが、問題なく判定できた
  - 公式アプリ側の入力の遅れ・化けはなし（唐川さん確認）
- 画面：`2026-11-26_test-result.jpg`

## 導入手順（実績）
1. Releases の test-latest から APK をダウンロードしてインストール
2. ユーザー補助 → ダウンロード済みサービス →「投擲ウォッチャー」を ON
   （ONにできない場合は：設定 → アプリ → 投擲ウォッチャー → ︙ → 制限付き設定を許可）

## 次にやること
1. スマホ：拾った投擲を1投ずつ Firestore に送る（PCで出した連携コードを入力）
2. PC（darts-training-lab）：「スマホ連携」で連携コードを出し、届いた投擲をリアルタイム表示・記録
3. 唐川さん：Firebase コンソールで firestore.rules を更新（手順は作業時に案内）
4. ゲームの区切り：START/CHANGE と時間間隔で区切り、ゲーム種別は PC 側で後から選ぶ
